My Kitty Terminal Setup: The Config, the Tools, and the Rough Edges

2026-10-27·Vishal Jha

I spend a lot of time moving between code, build output, Markdown notes and remote machines. I wanted a terminal where those tasks felt connected: split a pane, read a file with formatting, find an old command, and tell at a glance when I had entered SSH.

This is the configuration I use on my Mac: Kitty, Zsh, Atom One Dark, MesloLGS NF, and a small collection of command-line tools. There is no Powerlevel10k or Starship prompt in these files. The powerline shapes at the top belong to Kitty’s tab bar, not the shell prompt.

This guide comes from inspecting my actual configuration and installed Kitty 0.48.2. It includes the complete files, portable executable paths and the rough edges I found while checking my old notes. It is a macOS guide; the appearance and shortcuts are not a promise of identical pixels on Linux or a different display.

1. What each layer does

Kitty draws the window, glyphs, cursor, panes and tabs. Zsh interprets commands and sets up aliases. The individual programs produce the coloured output. Changing a Kitty theme does not install syntax highlighting, a file browser or a Git pager.

2. Install the tools, then the configuration

Version boundary: those are the versions installed when I inspected the setup on October 27, 2026. Homebrew installs its current releases; it does not reproduce that version list. For a matching-version baseline, use the corresponding official release tags linked below and keep the bundled Piper revision. The bundle reproduces the configuration, not an entire macOS image. I checked these files on my Mac; I have not tested the entire installation on a clean Mac.

With Homebrew already installed:

brew install --cask kitty
brew install bat glow lsd yazi fzf zoxide git-delta fastfetch python

Install the four MesloLGS NF font files—Regular, Bold, Italic and Bold Italic—using Font Book. This is the font family my config names. A similarly named Nerd Font may need a different font_family value. You do not need to install the Powerlevel10k prompt to use its font.

My Kitty app lives in ~/Applications/kitty.app, and several tools live in ~/bin. Homebrew will normally use different paths. The download contains two templates and a small preparation script that substitutes the paths returned by command -v. It writes only inside the extracted download, not into your live configuration:

cd "$HOME/Downloads/kitty-setup"
python3 prepare.py
less kitty/kitty.conf
less yazi/yazi.toml

The bundle’s README.md has the complete backup and copy commands. Back up first, then copy the three Kitty files together. Merge the shell snippet into your existing setup rather than replace your entire .zshrc; it may contain unrelated configuration. The resulting layout is:

~/.config/kitty/
  kitty.conf
  theme.conf
  tab_bar.py
~/.config/terminal-setup/terminal.zsh
~/.config/yazi/
  yazi.toml
  plugins/piper.yazi/main.lua
  plugins/piper.yazi/LICENSE
~/Library/Preferences/glow/glow.yml

Source the shell snippet once, near the end of ~/.zshrc:

source "$HOME/.config/terminal-setup/terminal.zsh"

Ensure Homebrew is already on your shell’s PATH. My Apple Silicon login profile uses eval "$(/opt/homebrew/bin/brew shellenv zsh)"; Intel Macs usually have a different prefix. The guide assumes standard config locations, not a custom ZDOTDIR or XDG_CONFIG_HOME. Save work and open a fresh Kitty window after installing.

3. The appearance: one palette, several renderers

My font settings are small enough to keep together:

font_family MesloLGS NF
bold_font auto
italic_font auto
bold_italic_font auto
font_size 14.0
text_composition_strategy 1.7 30
disable_ligatures never
macos_thicken_font 0.25

The two composition numbers are gamma and contrast adjustments, not font weights. Allowing ligatures does not add ligatures to a font that lacks them. These are appearance preferences, not measured performance improvements.

The background is #282c34, text is #abb2bf, cyan is #56b6c2, blue is #61afef, green is #98c379, and red is #e06c75. The complete 16-colour palette is in theme.conf. Bat and delta use TwoDark; Glow uses its own dark rendering, so not every application shares identical colour tokens.

window_padding_width 10
background_opacity 0.95
dynamic_background_opacity yes
background_blur 24
hide_window_decorations titlebar-only
initial_window_width 120c
initial_window_height 34c
remember_window_size yes

The initial dimensions are character cells. Once Kitty remembers a window size, that saved size can take precedence. The 95% opacity and blur mean the desktop behind the window also affects its appearance.

cursor_shape beam
cursor_blink_interval 0.5
cursor_trail 1
cursor_trail_decay 0.1 0.4
repaint_delay 8
input_delay 2
sync_to_monitor yes

cursor_trail 1 is a millisecond threshold, not a one-pixel trail. The decay values control its fade timing. The repaint and input delays are batching controls; they are not measured end-to-end typing latency, and monitor synchronisation still limits rendering. Lower values can cost CPU. Blur is another possible cost. See Kitty’s configuration reference for the actual semantics.

4. Panes, tabs and the legend

Kitty calls a pane a window; an OS window contains tabs, and each tab contains those panes. My enabled layouts are splits,grid,stack,tall,fat. I use native panes here, not tmux. They do not keep a remote job alive after a lost SSH connection.

map cmd+d       launch --location=vsplit --cwd=current
map cmd+shift+d launch --location=hsplit --cwd=current
map cmd+g       goto_layout grid
map cmd+shift+g goto_layout splits

⌘G / ⇧⌘GGrid / manual splits layout
Ctrl+Shift+[ / ]Previous / next pane

⌘W or Ctrl+Shift+QClose the tab, not just the focused pane

My tab_bar.py delegates tab drawing to Kitty’s powerline renderer, then appends a colour-coded legend after the last tab. Cyan means pane actions, gold means tabs, and red means closing. The bar is shown even with one tab.

A correction to my old notes: the legend’s Option+Command+arrow reminder is not backed by a mapping in this snapshot. Shift+Command+Enter is not mapped to zoom either. Use the verified shortcuts above. The legend also skips itself when there is insufficient space; it is not literally always visible. Its simple character counting is not a perfect terminal-cell-width calculation.

If you want those extra bindings, add the following as an optional change. They are not part of my inspected configuration or the download:

map opt+cmd+left  neighboring_window left
map opt+cmd+right neighboring_window right
map opt+cmd+up    neighboring_window up
map opt+cmd+down  neighboring_window down
map cmd+shift+enter toggle_layout stack

5. The shell tools that make the theme useful

The default macOS Zsh prompt is sufficient for this setup. The important changes are the commands behind it:

alias md='glow -p'
alias mdcat='glow'
export GLAMOUR_STYLE=dark
alias cat='bat'
export BAT_THEME="TwoDark"
export MANPAGER="sh -c 'col -bx | bat -l man -p'"
export MANROFFOPT="-c"
alias ls='lsd --group-dirs first'
alias ll='lsd -l --group-dirs first'
alias la='lsd -la --group-dirs first'
alias lt='lsd --tree --depth 2'
source <(fzf --zsh)
eval "$(zoxide init zsh)"
alias ff='fastfetch'

Use command cat or \cat when you need plain output instead of bat. These are interactive aliases; scripts should call the program they actually need. md opens Glow’s pager, while mdcat prints Markdown directly. ff is optional and does not run at every shell startup.

fzf’s shell integration supplies Ctrl+R for history, Ctrl+T for files and Alt+C for directory selection. The --zsh integration requires fzf 0.48 or newer. My left Option key acts as Alt. The full snippet also colours fzf to match the palette. zoxide learns directories as I visit them; a fresh installation will not know my navigation history.

Yazi and rendered Markdown

⌘B launches Yazi in a side-by-side split using --bias=22. This requests a relatively narrow pane; its exact width depends on the active layout and available space. It is a normal terminal pane, not a special file-browser widget.

The missing dependency in many “copy my theme” guides is the previewer. My Yazi configuration routes .md, .markdown and .mdx files through Piper, which invokes Glow:

[[plugin.prepend_previewers]]
url = "*.md"
run = 'piper -- CLICOLOR_FORCE=1 /absolute/path/to/glow -w=$w -s=dark "$1"'

$w is the preview width and $1 is the selected path. MDX is treated as Markdown here; Glow is not running React components. An opener rule also makes opening these files run glow -p. The complete download contains all three rules, the opener, and my installed Piper code with its MIT licence. It does not fetch a moving plugin branch during setup.

Shift+Command+M uses Kitty path hints to open a selected on-screen path in a Glow overlay. It needs a real readable Markdown path; it is not an editor command. The preparation script resolves the executable path used by that mapping.

Git diffs

I configure delta separately from Zsh:

git config --global core.pager delta
git config --global delta.navigate true
git config --global delta.line-numbers true
git config --global delta.syntax-theme TwoDark

These change your global Git pager settings, so inspect existing values first. They enable navigation, line numbers and the TwoDark syntax theme. My inspected config does not enable side-by-side mode. The relevant upstream reference is delta’s configuration guide.

6. A colour cue for SSH

My Zsh ssh() wrapper changes the background to #1a1a2e, text to #f5f5f5, and the cursor to #ff5555 before calling the real SSH program. When it returns normally, the wrapper restores the three local colours and returns SSH’s exit status.

ssh() {
  local local_bg="#282c34" local_fg="#abb2bf" local_cursor="#528bff"
  local ssh_bg="#1a1a2e"   ssh_fg="#f5f5f5"   ssh_cursor="#ff5555"

  printf '\033]11;%s\007' "$ssh_bg"
  printf '\033]10;%s\007' "$ssh_fg"
  printf '\033]12;%s\007' "$ssh_cursor"

  TERM=xterm-256color command ssh "$@"
  local ec=$?

  printf '\033]11;%s\007' "$local_bg"
  printf '\033]10;%s\007' "$local_fg"
  printf '\033]12;%s\007' "$local_cursor"

  return $ec
}

OSC 10, 11 and 12 change text, background and cursor colours. command ssh prevents the wrapper calling itself. The TERM=xterm-256color fallback helps when a server lacks xterm-kitty terminfo, but it does not install remote aliases or force every remote program to use colour. Kitty’s SSH kitten is another approach; it is not what this wrapper uses.

This cue is deliberately limited. It changes colour even if authentication fails, does not prove which host I reached, and resets to hard-coded local colours rather than a saved stack. Nested sessions or an interrupted shell can leave an unexpected colour. It is a reminder, not a safety check. The wrapper is included so you can reproduce it, not because these edge cases are solved.

7. Verify it before relying on it

From a new Kitty shell, run:

command -v bat glow lsd yazi fzf zoxide delta fastfetch
alias cat ls md
whence -w fzf-history-widget z
bat --list-themes
cd "$HOME/Downloads/kitty-setup/examples"
ll
cat hello.cpp
md README.md

Then try ⌘D, Ctrl+Shift+W, ⌘B and a new tab. Test Ctrl+R with harmless commands rather than photograph real history. My font can be checked with Kitty’s kitten choose-fonts; verify the family and all four faces before changing anything.

SymptomWhat to check
Boxes instead of iconsMesloLGS NF is installed and the family name matches; reopen Kitty after font installation.
⌘B or Markdown hints failRun prepare.py after the tools are installed; inspect the resolved absolute paths.
Markdown preview is blankPiper files are present, Glow is executable, and Yazi/Piper versions are compatible.
Ctrl+R does nothingfzf --zsh was sourced once in the interactive shell; another plugin may override bindings.
Legend missingThe renderer omits it if the remaining tab-bar width is too small.
New shell has a plain promptExpected: this setup has no prompt framework.
Remote colours stay changedThe wrapper may not have returned normally; start a new shell/window or restore the three local colours.
Everything closed with ⌘WThat shortcut closes a tab; use Ctrl+Shift+W for one pane.

Two settings worth choosing deliberately

The inspected configuration uses confirm_os_window_close 0, which disables close confirmation, and allow_remote_control yes with listen_on unix:/tmp/mykitty. Remote control allows programs to operate Kitty, including sending text and reading window content; with this broad setting, terminal programs reached over SSH can also be a concern. These are real choices in the snapshot, not requirements for the colour theme or shortcuts.

For a safer variant, change remote control to no and remove listen_on; set close confirmation to -1 if you want Kitty to account for running commands. Review Kitty’s remote-control permissions before opting into the broad setting. Nothing in this guide changes my installed configuration automatically.

I keep 50,000 scrollback lines and a 100 MB pager-history allowance. Useful for build output, but scrollback can also contain sensitive command output. The download contains no history, SSH configuration, host addresses or credentials.

What I checked, and what remains manual

I checked the installed versions, read the files, parsed the configuration using the installed Kitty library, and compared effective shortcut mappings rather than trust the old README. I also checked the prepared bundle and the site build. That does not verify every interactive behaviour on a fresh Mac. Genuine terminal screenshots are not included in this version; the visual above is labelled as a diagram.

The most useful part of this setup is knowing which layer owns a behaviour. Kitty owns the panes. Zsh owns the aliases. Glow owns Markdown rendering. Once those boundaries are clear, the configuration becomes much easier to reproduce and debug.
